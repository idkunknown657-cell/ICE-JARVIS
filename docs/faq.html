Installing

Is it really free?

Yes. The app is free to download and use, and the source is published under CC BY-NC 4.0 — non-commercial use, no charge, no account, no upsell screen. You can read every line before running it.

Do I need Python installed?

No. The installer carries its own Python runtime and every library — that is most of why ICE-Setup.exe is ~119 MB.

Python 3.13 or 3.14 is only needed for the from-source route, where you clone the repository and double-click setup.bat.

Does installing it need administrator rights?

No. It installs for the current user only: nothing machine-wide, no services, no UAC prompt. It appears in Settings → Apps → Installed apps like any normal program, and uninstalls from there.

Windows says "Windows protected your PC". Is it a virus?

No — that is SmartScreen's reputation warning, which appears for any downloadable executable Microsoft has not seen enough times. A brand-new release of a small open-source project is exactly that case.

Click More info → Run anyway, or do what a cautious person does and check the SHA-256 first. The checksums are published beside every release.

Can I use it without installing anything?

Yes. Every release also ships ICE-JARVIS-Windows-x64.zip. Unpack it anywhere, run JARVIS.exe. No registry entries, no Start Menu group — good for a USB stick or for keeping two versions side by side.

Which systems does it run on?

Windows 10 and 11 (64-bit) is the target and the only platform the installer is built for. Linux and macOS work from source and are tested less.

Using it

How much does it cost to run?

Nothing, in the normal case. Replies come from an AI provider, and the free tiers are generous: Gemini is primary, and GROQ, Cerebras, OpenRouter and Hugging Face work as free fallbacks. If one provider rate-limits you, JARVIS moves to the next instead of failing.

If you want a paid tier later, you paste that key in ⚙ Settings → API Keys — nothing about the app changes.

Do I have to memorise commands?

No. There is no command list to learn. It understands intent, so "open Chrome and search for flights to Delhi", "turn the volume down", "what's on my screen" and "remind me in ten minutes" are all just sentences.

Which languages does it speak?

English, Hindi and Hinglish, and it handles the mix mid-sentence the way people actually talk. Emotional context is tracked as part of the conversation, so tone matters, not just words.

Does it work offline?

Partly, and it is worth being precise: the brain is a cloud model, so generating a new reply needs a connection. Everything else is local — memory, files, PC control, screen reading, the interface, the avatar, the update manifest check only happens when you allow it.

There is no bundled local model. If you want fully offline inference, this is not that app.

How does it update, and can I stop it?

On start it reads a small JSON manifest from the releases page, which carries the new version, its download URL and its SHA-256. If you accept, the payload is downloaded, hashed, and staged — then applied on the next restart by a script that waits for the app to exit, so files are never swapped under a running process.

Your data is not in the payload at all: no keys, no memory, no logs. You can point the app at a manifest you host yourself, or simply not update — nothing forces it.

Can I reach it from my phone?

Yes, with the optional local dashboard: a small server on your own PC that your phone connects to over TLS with an encrypted channel. It is off unless you turn it on, and it stays inside your network unless you deliberately expose it.

Privacy & safety

Does it send my data anywhere?

Only in these places, and nowhere else:

  • The AI provider you configured — the conversation you are having, so it can be answered.
  • The update manifest on GitHub — a plain read of a public file, when the app checks for updates.
  • Public data feeds — only when you ask a question about the world (aircraft, earthquakes, natural events, satellites). Keyless, read-only.
  • Your own mail server — only if you set up mail, and only for the mail you asked it to read or send.

No telemetry, no analytics, no accounts, no crash reporting. Nothing about you or your machine is sent along with any of those requests.

Where are my API keys stored?

In config/api_keys.json inside the app folder on your own PC. It is git-ignored, is never part of a release, and the build refuses to run if it detects a secret in the payload it is about to ship. Mail passwords are never spoken, logged or shown back in the interface.

Is the microphone always listening and uploading?

The mic tile on the Home screen is a mute switch — click it and input stops. Windows' own microphone privacy gate applies to JARVIS like any other app, and ⚙ Settings → Voice & Language → Test measures real audio and tells you exactly which link is failing if it hears nothing.

Audio is used to transcribe what you said; it is not uploaded anywhere except as the text of your request to your own AI provider.

Giving an AI control of my mouse and keyboard sounds risky.

That is a reasonable instinct, so the app is built with brakes rather than assurances:

  • Autonomous mode is bounded — a goal and a time budget you set, and it reports what it did afterwards.
  • Sending anything is confirmed first — mail, for instance, stops at an on-screen confirmation showing the recipient and the text.
  • Self-training only changes what JARVIS believes. It can never edit settings, keys, permissions or files, never drives the mouse on its own, stops the moment you speak, and is entirely disabled when memory is off.
  • Nothing is hidden — every action is in the interface as it happens, and in logs/jarvis.log.
How do I get a completely clean slate?

Delete config/api_keys.json and memory/long_term.json — the app runs first-time setup again. Uninstalling asks first, and its default answer is keep my data, so a reinstall keeps your keys and memory.

Working on it

Can I read and build the code myself?

Yes — the repository is the app. Clone it, run setup.bat, and you are running from source in one step. Releases are built by GitHub Actions on tagged commits: freeze with PyInstaller, compile the installer with Inno Setup, selftest the packaged executable, then publish.

You can build your own installer too: installer/build_installer.py does the whole thing, and refuses to run if it finds a secret in what it is about to ship.

How stable is it, really?

1667 tests run on every push against Python 3.13 and 3.14, and a smoke test of the packaged JARVIS.exe runs before a release is allowed out. The packaged build also supports JARVIS.exe --selftest, which verifies every module and data file the build claims to contain — it has already caught installs that looked healthy while all 42 of their abilities were missing.

The test suite runs on your machine with one command, so you do not have to trust a badge: python -m unittest discover -s tests.

Something is broken. Where do I look?

Start ICE JARVIS (debug console) from the Start Menu — same app, output attached, everything mirrored to logs/jarvis.log. A startup crash writes logs/startup-crash.log and tells you where it is.

Then open an issue with the log and what you expected. It is a small project, so a clear report is genuinely useful.

Can I add my own tools?

Yes — there is a documented plugin API and examples in the repository's plugins/ folder. The tool loader discovers them by scanning that folder, so a new plugin is a file, not a rebuild.

Why is it called ICE?

Because a companion that is calm, clear and quietly capable felt like ice rather than fire — and because the core on the home screen looks better frozen than burning.
