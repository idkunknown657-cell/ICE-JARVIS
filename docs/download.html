Which file do I want?

FileSizeYou want it if…
ICE-Setup.exe~119 MBYou want it installed properly: Start Menu, uninstall entry, automatic updates. This is the normal choice.
ICE-JARVIS-Windows-x64.zip~160 MBYou would rather not install anything, want it on a USB stick, or want to keep several versions side by side.
SHA256SUMS.txttinyYou want to prove the file you downloaded is the file that was published. Recommended once per download.
update.jsontinyYou are curating your own update channel, or just curious what version and hash the app will look for.
Why is it so large? The package carries an entire Python runtime, every library, and the Playwright driver, so that no machine needs Python installed. About 365 MB unpacked.

Verify a download

Hashing takes a few seconds and tells you the file arrived intact and unmodified. Grab SHA256SUMS.txt from the same release, then run one of these in the folder you downloaded into.

Windows — built in, no downloads

certutil -hashfile ICE-Setup.exe SHA256

The result should match the ICE-Setup.exe line in SHA256SUMS.txt. Case does not matter; whitespace does not either. If both hashes match, the file is bit-for-bit what was built and published.

PowerShell

(Get-FileHash .\ICE-Setup.exe -Algorithm SHA256).Hash

macOS / Linux

shasum -a 256 ICE-JARVIS-Windows-x64.zip      # macOS
sha256sum ICE-JARVIS-Windows-x64.zip          # Linux
If the hash does not match, do not run the file. Delete it, download again from the release page, and if it still disagrees, open an issue — a mismatch means the file is not the one we published.
You can also check the build itself. The installed app supports JARVIS.exe --selftest, which imports every module the build claims to contain plus the data files it reads from disk, and exits non-zero if anything is missing. CI runs it before a release is allowed to publish.

All versions

The latest-release block above lists every published version with its files, sizes and download counts — read live, so it can never drift. Older versions stay available; nothing is ever deleted.

A tag does not always mean files: if a release build fails, the tag exists with nothing attached to it. That is deliberate — a failed build publishes nothing rather than something half-built.

Notes for each version live in the changelog, and the build log for every release is in Actions.
